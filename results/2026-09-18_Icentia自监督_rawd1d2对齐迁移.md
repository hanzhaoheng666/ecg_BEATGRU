# Icentia SSL 与目标 `raw+d1+d2` 输入完全对齐

## 设置

上一版 Icentia SSL 只预训练 raw，目标 CNN 才加入 d1/d2。本实验在 Icentia 预训练阶段就构造完全相同的 `raw+d1+d2` 三通道因果窗口，再迁移 4 个卷积块到单导联 MIT-BIH 模型。窗口、RR、DS1/DS2 划分和冻结评估口径均不变。

## 结果

| 方法 | DS2 Macro / S / V | INCART Macro / S / V | SVDB Macro / S / V |
|---|---:|---:|---:|
| 从头训练单导联 | 0.9115 / 0.7987 / 0.9472 | 0.8117 / 0.5873 / 0.8653 | 0.5718 / 0.2849 / 0.5043 |
| Icentia SSL（raw-only） | 0.8784 / 0.7033 / 0.9468 | 0.8091 / 0.6015 / 0.8461 | 0.5455 / 0.2809 / 0.4412 |
| **Icentia SSL（raw+d1+d2 对齐）** | **0.9085 / 0.7888 / 0.9477** | **0.8207 / 0.5909 / 0.8856** | 0.4825 / 0.1333 / 0.4087 |

输入对齐后，相比 raw-only SSL，DS2 Macro-F1 提升约 0.0301、INCART 提升约 0.0116；但 SVDB Macro-F1 下降约 0.0629，S/V 都下降。与从头训练相比，DS2 已接近但仍低 0.0030，INCART 略高 0.0090，SVDB 明显低 0.0893。

## 判断

`raw+d1+d2` 对齐是必要的实现修复，但不是跨域泛化的充分条件。它说明之前 raw-only SSL 的输入错配确实造成了部分损失；SVDB 的剩余问题更像采样率/设备/导联语义和形态分布偏移，而不是单纯输入通道数量。当前仍不建议用该预训练模型替换从头训练主模型。

原始输出：`runs/icentia_ssl_rawd1d2_20260918/`（预训练）和 `runs/icentia_ssl_rawd1d2_transfer_20260918/`（迁移）。
